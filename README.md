Для работы был выбран FastAPI, поскольку его использовали на лекции и мне показалось, что это чаще всего используемый фреймворк.
Анализировались следующие метрики: Latency - время ответа пользователю, P50, P95, P99 - время, такое что за это время или быстрее будет выполнено 50%, 95%, 99% запросов соотвественно. Целевой порог - 20 мс для P50, 30 мс P95 и 50 мс для P99. 50-100 мс для пользователя это почти мгновенно, 500 - небольшая задержка. Если целевые показатели не достигаются, нужно менять скрипт. Но для маленькой модели, такой как mini-frida такие целевые показатели вполне достижимы. Метрика Throughput (RPS) - это сколько запросов может выполнить сервис в секунду. Целевое значение - 20. В случае если не достигнуты уелевые значения, нужно проверить правильность арботы с ассинхронностью. Model inference time - это время, которое займет обработка входных данных и получение выходных данных. Целевое значение - 750 мс. Если оно не достигнуто, нужно переписывать код модели. CPU usage - это сколько CPU уйдет на контейнер. Memory usage -это сколько памяти уйдет на контейнер. Целевое значение - 2 Гб. В случае если оно не достигается, нужно замерять используемую память в ходе эксперимента и следить за расходом памяти. Для анализа важны все метрики.
Были получены следующие значения: P50 = 15.65 мс, P95 = 21.18 мс, P99 = 25.88 мс, среднее значение 16.34 мс.
