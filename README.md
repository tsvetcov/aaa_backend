Для работы был выбран FastAPI, поскольку его использовали на лекции и мне показалось, что это чаще всего используемый фреймворк.

Анализировались следующие метрики: Latency - время ответа пользователю, P50, P95, P99 - время, такое что за это время или быстрее будет выполнено 50%, 95%, 99% запросов соотвественно. Целевой порог - 20 мс для P50, 30 мс P95 и 50 мс для P99. 50-100 мс для пользователя это почти мгновенно, 500 - небольшая задержка. Если целевые показатели не достигаются, нужно менять скрипт. Но для маленькой модели, такой как mini-frida такие целевые показатели вполне достижимы. Метрика Throughput (RPS) - это сколько запросов может выполнить сервис в секунду. Целевое значение - 20. В случае если не достигнуты целевые значения, нужно проверить правильность арботы с ассинхронностью. Model inference time - это время, которое займет обработка входных данных и получение выходных данных. Целевое значение - 10 мс. Если оно не достигнуто, нужно переписывать код модели. CPU usage - это сколько CPU уйдет на контейнер. Memory usage -это сколько памяти уйдет на контейнер. Целевое значение - 2 Гб. В случае если оно не достигается, нужно замерять используемую память в ходе эксперимента и следить за расходом памяти. Для анализа важны все метрики.

Были получены следующие значения: P50 = 17.85 мс, P95 = 26.33 мс, P99 = 33.49 мс, среднее значение 19.06 мс, среднее значение inference\_time 9.27 мс, медианное значение inference\_time 8.41 мс. Это означает, что примерно половина времени уходит на работу самой модели. Показатели Total time = 37269.76 мс (время выполнения 2000 запросов), RPS = 53.66, WPS = 912.27, использованный объем CPU 537.39%, общий объем использованной памяти 615.27 Мб.
